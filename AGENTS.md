# AGENTS.md

Fork of [GodMode9](https://github.com/d0k3/GodMode9) (a bare-metal Nintendo 3DS firmware file browser, GPLv2) that adds a "cartridge corruption fixer". Written in C for the 3DS ARM9/ARM11, built into a `.firm` payload.

## Build

Prerequisites (must be installed, not vendored):
- `devkitARM`, with `DEVKITARM` env var pointing at it (`Makefile` errors out otherwise)
- `firmtool` Python package: `python3 -m pip install cryptography git+https://github.com/TuxSH/firmtool.git`
- Python 3.5+ and `p7zip` (`7za`), used by `utils/*.py` and the release zip step

Commands:
- `make firm` — build `output/GodMode9.firm` (+ `_dev.firm`)
- `make release` — clean build plus release zip in `release/` (this is what CI runs: `make release -j$(nproc)`)
- `make clean` — cleans all three subproject build dirs and `output/`/`release/`

`output/` and `release/` are gitignored. CI (.github/workflows/ci.yml) builds inside the `devkitpro/devkitarm` Docker container.

## Architecture

The final `.firm` is assembled by `firmtool` from **three ELFs**:
`arm9/arm9_code.elf`, `arm9/arm9_data.elf`, `arm11/arm11.elf`.

- `arm9/` — the actual GodMode9 application (UI, filesystem, crypto, gamecart). Main entry is `arm9/source/main.c`; menu/action wiring is in `arm9/source/godmode.c`.
- `arm11/` — small helper binary (FIRM launcher, exception handlers).
- `common/` — code compiled into both ARM9 and ARM11 (spi/pxi/shmem/etc.). Included via `INCLUDE := -I"$(shell pwd)/common"`.

Build order matters and is enforced in the root `Makefile`: `arm9_data.elf` depends on the VRAM tar (`data/*`, ~3MB hard limit) and on generated `arm9/source/language.inl`; `arm9_code.elf` depends on `arm9_data.elf`.

## Build-time flags (Makefile.common)

Select behavior/flavor via `make VAR=1`:
- `FLAVOR=SafeMode9` / `GodMode64` / `BrickedMode9` / `ZuishMode9` (default `GodMode9`)
- `NTRBOOT=1` — sign with SPI (ntrboot) keys instead of NAND; also pulls `resources/gm9/scripts/*` into the VRAM tar
- `SWITCH_SCREENS=1`, `SCRIPT_RUNNER=1`, `LARGEDLC=1`, `NO_LUA=1`, `SALTMODE=1`, `AUTO_UNLOCK=1`, `TIMER_UNLOCK=1`, `HIDE_HIDDEN=1`, `SHOW_FREE=1`, `MONITOR_HEAP=1`
- `FIXED_BRIGHTNESS=n`, `SD_TIMEOUT=n`, `N_PANES=n`
- `FIXER_SIM=1` — internal fault-injection test firmware (`output/GodMode9_sim.firm`). **Never for
  end users / never shipped** (see below).

## SIM test build — INTERNAL ONLY, never ship

`make FIXER_SIM=1 firm` builds `output/GodMode9_sim.firm`, a development-only firmware that injects
cartridge read faults so the fixer can be tested without a defective cartridge. It must **never** be
distributed to end users and is never part of a release.

Guarantees that keep it out of normal/end-user builds:
- Separate output name (`GodMode9_sim.firm`) **and** a separate object dir (`build_sim`) plus a
  flavor stamp that forces a relink, so a SIM object can never be linked into a normally-named firmware.
- `make release` rejects `FIXER_SIM` outright (`$(error ...)`).
- The entire SIM implementation lives under `#ifdef FIXER_SIM` (`arm9/source/utils/fixersim.c`); a
  normal build has **zero** SIM traces — no `FixerSim*` symbols and no `fixer_sim.cfg` / `SIM BUILD`
  strings (verify with `strings output/GodMode9.firm | grep -c fixer_sim.cfg` == 0).
- Runtime config `0:/gm9/out/fixer_sim.cfg` is read **only** by SIM builds; normal builds never open it.

Modes: `off`/`stuck`/`changing`/`recover`/`fail`/`slow`. Usage and scenarios: `notes/fixer-sim.md`.
The SIM build identifies itself: splash `*** SIM BUILD ***`, dashboard `CARTRIDGE FIXER (SIM)`, and a
`SIM BUILD: <status>` prompt when the fixer starts.

## Translations

Source of truth is `resources/languages/source.json`. Do **not** hand-edit generated files:
- `arm9/source/language.inl` — generated by `utils/transcp.py`
- `resources/gm9/languages/*.trf` — generated by `utils/transriff.py` from `resources/languages/*.json`
- `utils/transcheck.py` gates CI on a 30% translation threshold (crowdin workflows)

## Cartridge fixer feature (the fork's addition)

- `arm9/source/gamecart/command_ctr.c` — `CTR_CmdC5()` is the cartridge "refresh" command; `refresh_call_every` (default 10000) and `force_refresh` control how often it fires during reads.
- `arm9/source/gamecart/protocol_ctr.c` — bounded waits (stall watchdog) in `CTR_SendCommand`, so a dead cartridge aborts instead of hanging forever.
- `arm9/source/utils/gameutil.c` — the fix/verify loop: `CheckFixNcchHash()` and `AttemptFixNcsdFile()`, with the `bad_chunks`/`fixed_chunks` counters and hash-stuck retry logic. Also `FixerConfig` (`fixer_cfg`) and `FixerCfg_Load`/`FixerCfg_Save` (`0:/gm9/out/fixer.cfg`).
- `arm9/source/utils/fixerui.c` — the pre-flight config screen (`FixerUI_Preflight`) and the ALT-screen dashboard (phase/progress/counters/heartbeat).
- `arm9/source/godmode.c` — menu wiring: "Fix cartridge corruption" is only offered for mountable NCSD (`.3ds`) files (`corruptfix` path).

The refresh loop re-reads failing chunks up to the configurable **Retry limit** (default 500; preset
100–10000); the **Stuck limit** (default 50) gives up earlier on deterministic failures. The
"unfixable chunks" count and hash-stuck heuristics drive progress reporting (see README "Tracking
Repair Progress"). Note: with autoskip off and no Y held, a changing-hash block retries indefinitely
by design (the user can hold Y to skip).
